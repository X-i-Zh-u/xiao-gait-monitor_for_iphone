# GAIT iPhone Web Bluetooth 接收器

这个静态网页让 iPhone 通过 Bluefy 直接连接 `GAIT-L` 和 `GAIT-R`，不需要电脑上的 Python/Bleak 程序，也不修改当前鞋端固件。

## 已实现

- 左右鞋分别选择、连接和断线后重连
- 订阅现有 BLE GATT Notify 特征
- 解码协议版本 4 的 112 字节双样本通知
- 显示四路 ADC 电压、三轴加速度和三轴角速度
- 基于所选鞋侧的实时 IMU 数据估计二维步态轨迹，可开始、暂停、清空、校准前进方向并调整步长
- 使用左右鞋独立的固定 LM 直行模板，逐周期显示转弯、直行候选、不确定或数据无效，并提供开始／重新标定按钮
- 显示每只鞋的电池电压和估算百分比
- 每鞋统计近 2 秒接收率、累计平均、帧数、缺帧数和缺帧率
- 在 iPhone 通知回调入口记录接收时间
- 以 10 Hz 刷新无数据点的粗线曲线，接收和保存仍保持 50 Hz
- 记录期间将 CSV 分块写入 IndexedDB，停止后通过 iOS 系统分享面板保存文件

## 固件协议

| 项目 | 数值 |
|---|---|
| 左鞋名称 | `GAIT-L` |
| 右鞋名称 | `GAIT-R` |
| 服务 UUID | `c4a00001-8e22-4c04-a001-528400000001` |
| 通知特征 UUID | `c4a00002-8e22-4c04-a001-528400000001` |
| 通知长度 | 112 字节，连续两个 56 字节样本 |
| 单样本格式 | 小端序 `<BBBBIII10f` |
| 采样率 | 每鞋 50 Hz |
| 通知率 | 每鞋约 25 Hz |

网页要求协议版本为 4、采样率字段为 50 Hz，并检查数据包中的左右鞋编号。样本第4个字节保存电池电压编码，换算为 `3000 + code × 5` mV；255表示暂时不可用。页面显示电压与估算百分比，CSV增加`battery_mv`和`battery_percent`两列。当前固件要求 ATT MTU 至少为 115；Bluefy 网页无法读取实际 MTU，因此用“订阅后能否收到 112 字节通知”判断兼容性。

## 在 iPhone 上使用

1. 从 App Store 安装 Bluefy Web BLE Browser。
2. 将本目录部署到任意 HTTPS 静态网站。页面资源全部使用相对路径，可以部署在网站子目录。
3. 在 Bluefy 中打开部署后的 `index.html`。
4. 给两只鞋上电。
5. 点击左鞋“选择并连接”，在系统列表选择 `GAIT-L`。
6. 点击右鞋“选择并连接”，选择 `GAIT-R`。
7. 两侧显示“接收中”且帧号持续增加后，可以开始记录。
8. 如需转弯判定，点击“开始转弯检测”，让鞋静止约 0.4 秒，再开始行走。之后可点击“重新标定转弯检测”重新采集静止偏置并清空判定周期。
9. 停止记录后点击“保存/分享CSV”。
10. 在 iOS 系统分享面板中选择“存储到文件”。如果当前浏览器不支持文件分享，网页才会回退到普通下载。

普通 Safari 不提供 Web Bluetooth，不能直接使用本页面连接鞋子。页面必须使用 HTTPS；普通局域网 HTTP 地址不满足 Bluefy 的安全连接要求。

## HTTPS 部署

最简单的方式是把 `iphone_web_ble` 中的网页资源文件一并部署到 GitHub Pages、Cloudflare Pages 或其他静态 HTTPS 网站。不需要服务器程序、数据库或构建步骤。

本地修改后，可以先在桌面 Chrome/Edge 的 `localhost` 环境检查界面；真正的蓝牙和双鞋测试必须在安装了 Bluefy 的真实 iPhone 上完成。

## 时间含义

- `received_time_iso`、`received_unix_ns`：iPhone 收到通知回调时的系统时间，实际分辨率为毫秒。
- `received_monotonic_ns`：页面启动后的单调时钟值。
- `received_s`：相对本页面第一条有效通知的接收时间。
- 同一条通知内的两个样本共享相同的接收时间。
- `plot_s`：根据 50 Hz 帧号展开的绘图时间，只用于显示连续曲线。
- `adc_us` 和 `imu_us`：鞋端本机时钟，左右鞋之间不能直接对齐。

## 使用限制

### 二维轨迹估计

轨迹位于页面数据区最下方，在实时曲线和实时数值之后；手机上的记录操作栏仍固定在屏幕底边。先连接左鞋或右鞋，在“轨迹来源”选择该鞋，输入一次实际步行测得的平均步长；校准方向时让鞋尖朝向预期路径的前方，然后点击“校准前进方向”和“开始”。暂停会保留路径，清空会重置轨迹和姿态估计。两鞋各自维护轨迹状态，切换来源不会合并两侧样本。

算法按帧号使用 50 Hz 时间步长，以陀螺仪积分四元数姿态，并在加速度模长接近重力时用重力方向做互补修正。姿态补偿后的竖直动态加速度峰值用于步态事件检测；每个事件按用户设置的固定步长推进位置。四路 ADC 是未经标定的电压，固件未定义足底压力映射，因此不将其用作支撑期检测。算法没有已知地磁航向或外部位置参考，陀螺仪偏置会造成转向漂移，固定步长也无法适应每一步长度变化；累积距离和路径会随步数增长而偏离真实轨迹。方向校准只重设当前水平朝向，不会消除后续陀螺仪漂移。该显示用于短距离、定性二维观察，不是测绘级定位。

### LM 转弯判定

转弯结果位于实时数值区之后、二维轨迹之前，左右鞋分别显示。按钮第一次点击启动检测；再次点击重新标定两鞋的静止陀螺仪偏置，并重置周期状态。它不会用当前数据重新训练固定的 4 km/h 直行 LM 模板。未连接的鞋可在之后收到数据时完成自己的静止标定；断线后该鞋会重新等待标定。

算法使用鞋端 50 Hz 样本和 ADC/IMU 微秒时间戳，基于静止时约 0.4 秒的 `gyro_y` 偏置估计、50 ms 因果低通后的负向 `gyro_y` 峰值划分候选周期。左鞋 LM 原始通道按 0、1、2、3，右鞋按 3、2、1、0 映射到内侧后跟、内侧前掌、外侧前掌、外侧后跟。每周期从前后各 10% 原始电压提取基线，对 LM 电压做 50 ms 因果低通，按固定训练阈值查找持续至少 40 ms 的响应开始和恢复，提取主响应开始与峰值相位。得分是四通道相对模板的开始相位绝对差中位数、峰值相位绝对差中位数二者的较大值，单位为“周期百分比”；它不是概率或置信度。有效通道少于两路时为“数据无效”。得分至少 5.00% 为“转弯”，不超过 3.25% 为“直行候选”，两者之间为“不确定”。判定在完整候选周期结束后更新，因此通常有约一个步态周期的延迟。

候选周期由 IMU 峰值划分，并不是视频确认的真实落脚事件。LM 值是电压响应，不能当作压力、力或弯曲角度。此算法不判断左转或右转。固定模板来自同一受试者、同次佩戴的 4 km/h 直行实验；交接材料报告的 98.9% 是该批数据的内部验证结果，不能推断在线、换鞋、跨佩戴或跨受试者精度。手机页面仍需用真实鞋载数据做现场核验和必要的模板重建。

- 第一次选择设备必须由用户点击按钮并在 iOS 设备列表确认，网页不能静默连接陌生设备。
- 当前页面打开期间发生断线，会尝试重新连接已经授权的设备；页面刷新后通常需要重新选择。
- 采集期间应保持 Bluefy 在前台并避免锁屏。
- 浏览器无法强制连接间隔、2M PHY 或 MTU，这些参数由 iOS 和鞋端协商。
- 当前固件没有应用层历史数据补传，断线期间丢失的帧不能由网页恢复。
- CSV 生成后必须点击“保存/分享CSV”，并在系统面板选择“存储到文件”；仅显示“CSV已生成”不代表文件已经保存到“文件”应用。
